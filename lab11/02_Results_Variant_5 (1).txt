РЕЗУЛЬТАТЫ СИМУЛЯЦИИ
Лабораторная работа №11 — Вариант 5: Библиотека

Дата: 2026-11-15
Seed: 42 (фиксированный)
N = 12 000 документов (выдач)
Q = 30 000 запросов
SHARDS = 3

Поля:
  reader_id  — идентификатор читателя (0..2499)
  genre_id   — жанр книги (0..4)
  loan_id    — последовательный id выдачи

======================================================================
1. ИСХОДНЫЙ КОД (simulation_v5.py)
======================================================================
import random, hashlib
from collections import Counter

random.seed(42)
N, Q, SHARDS = 12000, 30000, 3

rows = [dict(reader_id=i % 2500, genre_id=i % 5, loan_id=i) for i in range(N)]

def stable_hash(value):
    digest = hashlib.sha256(str(value).encode()).digest()
    return int.from_bytes(digest[:8], 'big')

def low_card(row):
    return row['genre_id'] % SHARDS

def hashed_reader(row):
    return stable_hash(row['reader_id']) % SHARDS

def range_loan(row):
    return min(row['loan_id'] // (N // SHARDS), SHARDS - 1)

def describe(name, assign, requests):
    docs = Counter(assign(r) for r in rows)
    load = Counter(assign(r) for r in requests)
    d = [docs[i] for i in range(SHARDS)]
    q = [load[i] for i in range(SHARDS)]
    print(name, 'docs=', d, 'queries=', q,
          'doc_max_mean=', round(max(d)/(sum(d)/SHARDS), 2),
          'query_max_mean=', round(max(q)/(sum(q)/SHARDS), 2))

uniform = random.choices(rows, k=Q)
hot_rows = [r for r in rows if r['genre_id'] == 0]
hot = [random.choice(hot_rows) if random.random() < 0.6 else random.choice(rows)
       for _ in range(Q)]

for name, fn in [('genre_id', low_card),
                 ('hashed_reader', hashed_reader),
                 ('range_loan', range_loan)]:
    describe(name + '/uniform', fn, uniform)
    describe(name + '/hot', fn, hot)

4. АНАЛИЗ
======================================================================
• genre_id (низкая кардинальность = 5):
  - Документы уже перекошены.
  - При hot-нагрузке (60 % запросов к одному жанру) max/mean = 2.28 → сильный горячий шард.

• hashed_reader:
  - Документы и запросы распределены стабильно (max/mean ≈ 1.08–1.10).
  - Даже при hot-нагрузке по жанру перекос почти не появляется.
  - Лучший кандидат.

• range_loan:
  - Идеально ровные документы и запросы в симуляции.
  - В реальности монотонный loan_id создаёт «горячий хвост» при последовательных вставках.

Вывод: равномерное количество документов НЕ гарантирует равномерную нагрузку
(особенно видно на genre_id/hot).
